## 2026-10-30

### ① 프롬프트 변경

**요청 다듬기 — 바로 코드를 짜지 않고 설계부터**
- 처음 요청: 서비스 흐름, 원칙, 기술 조건을 주고 "먼저 화면 구성과 데이터 구조를 제안해줘"
- 바뀐 점: AI가 제안 끝에 확인 질문 4개(역량 이름, 키워드 개수, 추가 질문 시점, 스택)를 올렸고, 사용자가 답하면서 요구사항이 구체화됨
- 이유: 참고자료와 요청 사이에 다른 부분(역량 이름, 키워드 개수)이 있어서 코드를 쓰기 전에 정해야 했음

**요구사항 변경 — 역량 키워드**
- 전: "역량 키워드를 한 문장으로 정의" (AI는 '후보 여러 개 중 대표 1개'로 제안)
- 후: "키워드 1개당 한 문장. 키워드 버튼을 둬서 누르면 그 키워드의 한 문장이 보이게"
- 이유: 완성본 예시처럼 경험 하나에서 키워드가 여러 개 나오므로, 키워드마다 문장을 붙이고 버튼으로 골라 보는 방식이 더 맞음

**프롬프트.md 처음 작성** (변경 전 없음 → 작성)
- 공통 원칙: 사용자 요청의 원칙 4개 + 사용자가 고친 내용 우선, 반말·오타 허용, 호칭 쓰지 않기
- 질문 생성: 참고자료 대화 기록의 1차 질문을 좋은 예시로 넣음 (대안 비교, 의견이 갈린 순간)
- 추가 질문: 대화 기록 2·3차 질문에서 판단 기준을 뽑아 넣음 (모호한 답, 판단 근거 없음, 규모 미확인, 앞뒤 모순, 인상적인 말의 뒷이야기). 질문마다 "왜 묻는지" 한 줄
- STAR 원고: 완성본의 행동 항목 형식(소제목 + 근거와 판단)을 예시로 넣음. 하지 못한 것은 괄호로 정직하게
- 역량 키워드: 강의 자료의 "임팩트 있는 한 문장" 기준 + 완성본 예시
- 사용자 요청의 5개에 3개를 더 나눔: 전체 점검, 역량 매칭, 스토리 추가 질문 (각자 따로 호출되는 작업이라 지시문도 분리)

### ③ AI 실수와 수정

- **브라우저 점검 스크립트의 선택자 오류**: "대표 키워드" 글자를 찾는 코드가 안내 문장 속 같은 단어까지 잡아 점검이 멈춤. 오류 메시지로 발견 → 정확히 일치하는 글자만 찾도록 고침. 앱 자체 문제는 아니었음
- **모바일에서 단계 탭이 잘림**: 375px 화면 캡처를 보고 "4 역량 매칭" 탭이 잘린 것을 발견 → 모바일에서는 짧은 이름(질문/원고/키워드/매칭)을 쓰도록 고침
- **TypeScript 7 설치**: 최신 버전을 그대로 설치했더니 TypeScript 7이 들어옴. Next.js와의 호환이 확실하지 않아 TypeScript 5로 고정

## 2026-10-30 (2차 작업: 스토리 완성 + 메인 홈)

### ① 프롬프트 변경

**프롬프트.md — 역량 매칭**
- 전: "역량 7개 각각에 대해 구체적 장면이 있으면 매칭한다. 보통 3~5개가 적당하다." / 응답: `competencyId`, `scene`
- 후: "대표 역량 1개 + 보조 역량 0~2개(최대 3개). 대표 = 가장 강하게 증명하는 역량, 보조 = 장면이 분명할 때만. 그 장면이 나오는 행동 항목 번호(`actionNumbers`)도 돌려준다." / 응답: `competencyId`, `role`, `scene`, `actionNumbers`
- 이유: 사용자가 "경험 하나 = 대표 1 + 보조 최대 2"로 규칙을 정함. 홈 카드에서 선택한 역량과 관련된 행동을 강조하려면 행동 번호가 필요. 원고의 행동 목록에 번호(1, 2, 3…)를 붙여 보내도록 코드도 바꿈
- 안전장치: AI가 규칙을 어겨도 코드(`normalizeMatches`)가 중복 제거, 대표 1개, 보조 2개, 범위 밖 행동 번호 제거로 정리

**프롬프트.md — 스토리 작성(글자 수 기준)**
- 전: "본문(소제목 제외, 공백 포함)이 글자 수의 90~100%"
- 후: "소제목과 본문을 합친 글자 수(공백·줄바꿈 포함, 복사해서 붙여 넣는 글 기준)가 90~100%, 절대 넘지 않게"
- 이유: 화면은 복사되는 글(소제목 + 빈 줄 + 본문) 기준으로 글자 수를 세므로, AI 기준과 화면 기준을 맞춤. 자기소개서 입력칸에 소제목까지 함께 붙여 넣는 경우가 많아 넘치지 않게 함

**사용자 요청 변경**
- 역량 연결: "켜고 끄기(개수 제한 없음)" → "대표 1개 + 보조 최대 2개, AI 제안 후 사용자가 확인·변경"
- 순서: AI는 "홈 먼저, 스토리 버튼은 준비 중"과 "스토리 먼저"를 물었고, 사용자가 "스토리 먼저"로 정함

### ③ AI 실수와 수정

- **이미지가 안 보였던 일**: 사용자가 "첨부한 이미지 2장"을 언급했지만 AI에게 도착하지 않음. AI가 "이미지가 오지 않았다"고 알렸고, 사용자가 참고자료 폴더에 넣어 해결. 사용자는 "이미지 두 장이 뭘 말하는 거냐"고 되물었는데, AI가 처음에 어떤 문장을 근거로 이미지를 찾았는지 함께 보여 줬으면 덜 헷갈렸을 것
- **"스토리로 완성하기 기능이 왜 없어"** (사용자 지적): AI의 1차 보고("스토리 화면은 아직 없다")가 짧아서, 결과물이 나온 뒤 쓰는 기능이 아직 안 만들어진 상태라는 점이 분명하게 전달되지 않음. 원래 요청한 순서(핵심 흐름 → 스토리)를 근거로 설명하고, 홈보다 스토리를 먼저 만들어 해결
- **홈 카드의 "수정" 링크가 엉뚱한 화면을 엶**: 자동 점검에서 발견. 링크로 이동하면 Next.js가 화면을 먼저 그리고 주소를 나중에 바꾸는데, 코드가 주소를 너무 일찍 읽음. Next.js의 `useSearchParams`로 바꿔 해결
- **성능 개선 시도가 오히려 느려짐**: 구슬에 GPU 레이어(`will-change`)를 미리 지정했더니, GPU 없는 점검 환경에서 모바일 캐러셀이 27fps → 14fps로 떨어짐. 측정으로 발견해 되돌리고, 대신 (1) 카드 갱신을 낮은 우선순위로 미룸 (2) 모바일에서 쓰지 않는 빛 레이어 제거·blur 축소로 바꿔 39~47fps로 개선
- **스크롤 연동 애니메이션 효과는 불분명**: 측정할 때마다 결과가 크게 흔들려(12~30fps) 효과를 판단하지 못함. 원리상 메인 스레드 작업을 줄이는 방식이라 유지하되, 실제 기기에서 확인할 일로 남김
- **점검 스크립트 오류 3건**: "500자" 버튼이 "1500자"까지 잡힘, 윈도우 클립보드의 줄바꿈(\r\n) 차이, 명령어 이스케이프 실수. 모두 점검 코드 문제였고 앱 문제는 아니었음

### ③ AI 실수와 수정
- **구슬 품질 부족** (사용자 지적): 1차 제안 때 AI가 "CSS로 레퍼런스의 80~90%를 낼 수 있다"고 했지만 실제 결과는 레퍼런스와 거리가 멀었음. 성능을 걱정해 WebGL을 피했는데, 실제로는 컨텍스트를 하나로 모으고 프레임 예산을 두면 WebGL이 CSS 블러 레이어보다 더 빨랐음(모바일 캐러셀 24~34fps → 38~40fps). 처음부터 "WebGL 하나로 모아 그리기"를 시안으로 만들어 비교했어야 함
- **바깥 빛의 네모 경계**: 첫 렌더에서 구슬 주변에 네모난 밝은 영역이 보임. 빛이 캔버스 가장자리에서 잘려서였음 → 가장자리 전에 0으로 줄어들게 수정

- **입력칸 포커스 테두리 두 겹** (사용자 지적): 입력칸에 파란 테두리·옅은 번짐 위로 두꺼운 바깥 테두리가 하나 더 생김. 원인은 공통 포커스 규칙(`:focus-visible`)을 CSS 층(layer) 밖에 써서, 입력칸의 "공통 표시 끄기" 클래스보다 항상 우선한 것. 공통 규칙을 base 층으로 옮겨 해결. 버튼 등 다른 요소의 키보드 포커스 표시는 그대로인지 함께 확인함 (처음 캡처가 색 전환 도중에 찍혀 옅게 보였으나, 전환이 끝난 뒤 다시 확인해 정상임을 확인)
- **홈 카드 모서리** (사용자 지적): 둥근 목록 상자 안의 강조 줄 바탕이 네모로 그려져 모서리 밖으로 나옴. 목록 상자에서 안쪽을 모서리에 맞춰 자르도록 수정. 색을 바꾸기 전엔 바탕이 거의 흰색이라 드러나지 않던 문제
- **로고 글자 정렬** (사용자 지적): 크기가 다른 영문·한글을 세로 가운데로 맞춰 한글이 떠 보임 → 글자 아랫선 정렬로 수정
- **답변 제출 후 화면이 위로 올라가 당황스러움** (사용자 지적, PC, 버튼 누른 직후): AI가 재현했을 때는 스크롤 위치가 그대로여서 바로 원인을 못 찾음. 대신 재현 중 발견한 문제 — 제출해도 화면이 거의 안 바뀜, 새 질문이 화면 밖에 생김, 누른 버튼이 사라지며 커서가 페이지 처음으로 감 — 를 정리해 제안. 사용자 선택으로 ① 제출한 답변 접기 ② 새 질문 위치로 이동 ③ 커서 관리를 적용. 제출 직후 화면 위치를 화면을 그리기 전에 직접 정해 줘서, 답변 묶음이 다시 그려질 때 브라우저가 스크롤 기준을 잃는 문제도 함께 막음
- **역량 연결 토글이 고장처럼 보임** (사용자 지적): 칸 너비가 글자 길이에 따라 달라 선택 칸 크기가 줄마다 다르고, "대표"만 파란 글자, 보조 2개가 차서 막힌 "보조"는 이유 없이 흐리게만 보였음(이유는 마우스를 올려야 보이는 title에만 있었음). 세 칸을 같은 너비 그리드로, 선택 칸은 모두 같은 흰 손잡이 + 검정 글자로, 막혔을 때는 목록 위에 이유와 푸는 방법을 글로 보여 주고 막힌 버튼과 연결(aria-describedby)함
- **경험 완성 후 화면이 맨 위로 올라감** (사용자 지적): 상태가 바뀌면(역량 연결 중 → 완성) "다음 단계 화면으로 이동 + 맨 위로" 규칙이 실행되는데, 완성 후에도 같은 역량 연결 화면을 보여 주므로 이동 없이 맨 위로만 올라갔음. 단계가 실제로 바뀔 때만 위로 올리도록 수정하고, 흐름 점검에 "완성 전후 스크롤 위치·완성 안내가 화면 안에 있는지" 확인을 추가함
- **스토리 완성으로 이어지는 길이 없음** (사용자 지적): 경험을 완성하면 "홈에서 보기 / 새 경험 추가"만 있어 서비스의 마지막 결과물(자기소개서 글)을 모르고 지나칠 수 있었음. 처음 흐름을 짤 때 스토리를 "언제든 열 수 있는 별도 단계"로만 두고, 완성 직후의 다음 행동으로 연결하지 않은 것이 원인. AI가 제안(주요 버튼 하나 + 보조 버튼, 탭에 점)하고 사용자 확인 후 적용
- **스토리 탭 양옆에 테두리가 생김** (사용자 지적): 키보드 포커스 표시가 가로 스크롤 영역(탭 줄)에 위쪽이 잘려 세로줄 두 개처럼 보였음. 마우스 클릭으로는 켜지지 않는 것을 확인했고, 탭은 포커스 표시를 안쪽에 그리도록 수정
- **"새 글 쓰기"가 새 경험처럼 읽힘** (사용자 질문): 같은 경험으로 다른 문항의 글을 하나 더 쓰는 버튼이었음. 문구가 무엇을 새로 만드는지 말하지 않았던 것이 원인. "다른 문항으로 쓰기"로 바꾸고 글 목록 끝으로 옮김. 마무리 영역의 "역량 연결하기"는 아직 그 단계가 열리지 않은 사람도 볼 수 있어 "이어서 정리하기"(지금 진행 중인 단계로 이동)로 정함
- **어떤 구슬이 선택됐는지 알기 어려움** (사용자 지적): 선택을 "가장 밝고 활발하게"로만 보여 줬는데, 채워진 구슬은 모두 빛나고 빈 구슬은 모두 회색이라 차이가 거의 없었음. 색·밝기를 "경험이 있는지"와 "선택"에 함께 써서 두 의미가 섞인 설계 실수. 선택은 구슬 아래 잉크색 막대 + 선택 안 된 구슬을 작고 흐리게로 따로 보여 주고, 선택된 빈 구슬은 색을 옅게 비추기로 함(사용자 확인)
- **빈 구슬이 처음에 비어 보임** (AI가 캡처에서 발견): 빈 구슬은 성능 때문에 5프레임마다 그리는데 첫 장면도 그 규칙을 따라 화면을 연 직후 잠깐 비어 있었음 → 첫 장면은 바로 그리도록 수정
- **홈 카드 칸이 길어 아래 "행동"이 안 보임** (사용자 지적): 예시 글은 짧아 문제가 없었지만, 실제 사용자 글은 결과가 13줄까지 길어져 칸이 화면을 다 차지함. 예시 데이터로만 확인한 것이 원인. 칸 글을 5줄로 줄이고 넘치는 칸에만 [더 보기]를 두는 방식으로 수정(사용자 제안)
- **버튼을 바꾸자 "수정"이 다음 줄로 내려감** (사용자 지적): 스토리 버튼에 1px 테두리를 더하면서 폭이 2px 늘었는데, 세 버튼이 칸에 거의 꽉 차 있던 상태라 줄이 넘어감. 바꾼 뒤 버튼 줄만 따로 확인하지 않은 것이 원인. 화면 폭 3가지와 긴 문구("스토리로 완성하기")까지 넣어 한 줄인지 재는 점검을 추가함

- **https·localhost에서만 되는 기능을 그냥 씀** (사용자 지적으로 발견): 경험 번호를 crypto.randomUUID로만 만들었는데, PC(localhost)에서만 점검해 와서 http 주소에서는 이 기능이 없다는 점을 몰랐음. 휴대폰으로 개발 서버를 열자 새 경험을 만들 수 없었음. 서버 기록의 브라우저 오류("crypto.randomUUID is not a function")로 원인을 찾고, 없을 때 getRandomValues로 만들게 고침. 같은 종류(안전한 주소 전용) 기능을 찾아보니 복사(navigator.clipboard)뿐이었고 이미 대체 방법이 있어 그대로 둠
